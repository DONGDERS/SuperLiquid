# Play Store bottom bar: 52.9.21-24 (85292100)

## Confirmed from the device and dex

- Package `com.android.vending`, launcher alias `.AssetBrowserActivity`, actual resumed activity `com.google.android.finsky.activities.MainActivity`. A single full-screen `ComposeView` hosts the page **and** the bottom bar. Do not hide, scale, reparent, or mirror that view. Its five bottom AndroidView children supply icons, not labels.
- `Lamwa.a` lists the tabs in order. `Latis.eY` iterates the list and compares the loop index directly with `Lamwa.b`. Use that model as the selection source, rather than the selected flag of an embedded icon. Both `Latis.ff` and `Latis.fg` receive the model as argument zero.
- Legacy: `ff → hq → fvt.b → fvo → fvt.a`. Material: `fg → bmrx.cT → fsv.a → fsw.a`; the examined `ffm` implementation also calls `fvt.b`, via `fsx`. `fg` additionally adds a rectangular fill with `bcn.c` ahead of the surface.
- `fvt.a` builds shadow, border, background, and clipping as separate modifiers. `bcn.b` adds a fill modifier; its `bcq.gR` implementation draws the fill before `jaj.H()` draws the content. **Do not** hook `bcn` or `fvt` unconditionally: they are shared with other Compose surfaces. **Do not** drop `eX` or `eV`: they render native tab content, and `eX` includes icon animation paths.
- The accessibility capture shows a row of five virtual tabs on the tested device. The selected virtual tab is focusable but not clickable; the other four are clickable. The icons alone are not valid click targets. Drag release dispatches the same callback as the native tab item (`Lamwa.f.a.le(index)`); `Lamwa.b` confirms the change.

## Implementation and device checks

- Exact-build gate; tag bottom-bar background modifiers and their draw nodes using identity. Check the actual Compose host and five live AndroidView slots before replacing the fill. The replacement invokes the native draw-content callback once and leaves foreground, shape clipping and navigation untouched.
- The shared installer creates the two embedded `LiquidGlassPanel`s; the Play-only neutral Canvas renderer is removed. The panels can sample a page-only display list for refraction. Without an overlapping page layer, they retain the 86 material. Capturing the full Compose owner would include the foreground and the glass itself.
- `eX` creates a `rwk` callback with discriminator `0x12`, which draws the animated 56 × 32 dp selection background. Via `irc.a`, `iqy.gR` calls that background lambda then draws content. Skip only that lambda on the claimed live bottom bar. Check both geometry and `jsl.f` → `jud.x` layout ancestry; leave the icon, label and selection state untouched.
- Backdrop investigation: `jzz.dispatchDraw` enters `jud.Q` at the Compose root. `jtd.F` traverses placed children in draw order and calls `jud.Q` for each. This establishes the tree boundary, not a page-only capture point: a child can contain both page and navigation. `kdv.c` also runs `kdv.j` before drawing its graphics layer, so it is not a read-only replay API. `jbf.s` can replay an existing RenderNode, but it must not be used until the backing layer is positively identified as page-only and its position, clipping and draw order are verified. Never replay an ancestor of the claimed bar.
- Page capture candidate: both examined `vqz` branches emit a weighted content Box (the `inv.b` after `byy.b` and `ajlr.c`), compose its contents through `aggd.y`, and emit navigation later through `qid`. The `xmp` variant also emits a weighted content Box, invokes the page callback, then emits `qid` separately. Do not sample the outer scaffold. The use of weight and `BottomNavInsets` does not establish that the page draws beneath the bar; verify the placed bounds and clip on-device.
- Refraction integration: feed a page-only display list, recorded during its normal draw, into the shared panel's padded capture. Never redraw the page or sample the completed window. Verify owner, coordinate mapping, draw order and overlap. If there is no overlapping page content, retain material-only mode until an explicit underlap layout is designed and tested.
- A horizontal drag originating on the capsule cancels the native pointer stream once. Ordinary taps and vertical gestures remain native. The capsule waits for the native model to acknowledge the click before abandoning the optimistic selection.
